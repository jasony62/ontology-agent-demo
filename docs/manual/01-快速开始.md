# 01 快速开始

三种启动方式，任选其一。前提：已安装 Docker（方式一/二）或 Python 3.10+（方式三）。

## 方式一：一键脚本（macOS / Linux）

```bash
bash scripts/start.sh        # 自动创建 .venv、安装依赖、构建本体、启动 API+MCP
```

## 方式二：Docker（推荐，隔离环境）

```bash
docker compose up -d api mcp   # 构建并后台启动两个服务
docker compose ps              # 查看状态
```

## 方式三：手动

```bash
# 1. 创建虚拟环境并安装依赖（首次）
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt

# 2. 构建本体（可选，仓库已内置 domains/agent_task/agent_task_ontology.owl）
.venv/bin/python scripts/build_ontology.py

# 3. 启动推理 API + Demo 页面
.venv/bin/uvicorn api.main:app --host 127.0.0.1 --port 8000
# 另开终端启动 MCP（可选）
.venv/bin/python mcp/mcp_server.py --domain agent_task --port 9000
```

## 验证服务已就绪

```bash
curl -s http://127.0.0.1:8000/api/health
```

示例返回（数字是某一版本的运行快照，随本体与规则层变化，以实际返回为准）：

```json
{"status":"ok","ontology":"agent_task_ontology.owl",
 "reasoner":"OWL 2 RL (owlrl) + SHACL 业务规则（rules/*.ttl）+ 合规校验 R4",
 "domain":"agent_task","dirty":false,"agents":5,"tasks":9,
 "counts":{"agents":5,"tasks":9,"capabilities":5,"constraints":1,"assignments":0,"inferred_triples":811},
 "rules":{"ok":true,"total_derived":39,
          "files":[{"file":"R1_capability_coverage.ttl","derived_new":8,"error":null},
                   {"file":"R2_complex_task_delegation.ttl","derived_new":2,"error":null},
                   {"file":"R2a_certificate_validity.ttl","derived_new":4,"error":null},
                   {"file":"R2b_can_own.ttl","derived_new":8,"error":null},
                   {"file":"R5_high_risk_manual.ttl","derived_new":2,"error":null},
                   {"file":"R6_high_risk_second_review.ttl","derived_new":3,"error":null},
                   {"file":"R6a_can_review.ttl","derived_new":12,"error":null}]}}
```

（节选：省略 `contract`、耗时等字段；数字随本体与规则层变化，以实际返回为准。）

关键字段：`status=ok`、本体已加载；`inferred_triples` 是推理**新增**的三元组数（物化图 1208 − 原始断言 397 = 811），不是物化图总数；`POST /api/infer` 返回的 `added` 是**单次调用**的新增（重复调用通常为 0，偶有 1 条惰性断言，以实际返回为准），两者口径不同；`rules` 是规则层执行报告（哪些规则文件、各产出多少、有无错误）。

## 跑测试与一键演示

```bash
.venv/bin/python -m pytest tests/ -q     # 自动化测试套件（项数以 pytest 实测为准）
.venv/bin/python scripts/check_docs_numbers.py  # 手册运行快照数字自检（本体演进后跑）
bash scripts/demo.sh                     # 一键演示：能力匹配→编排→分配→一致性
```

## 停止服务

```bash
docker compose down                      # Docker 方式
# 手动方式：Ctrl+C 终止两个终端进程
```

## 导入本体后的只读体验（重要边界）

本服务支持加载自定义本体（见 [04 运维](04-运维与本体管理.md)）。**导入后运行态切换为框架内置的「导入的本体」只读领域**：页头徽标与「当前领域」页显示这份本体的真实文件名，说明 / 能力清单 / 示例题一起换；图谱 / 物化 / SPARQL / 通用查询与「查依据」可用，**领域专属推理（能力匹配 / 编排 / 合规）不可用**，V1 也不提供新建 / 修改 / 删除 / 覆盖本体。重启服务回到配置里的默认领域，导入文件仍留在 `data/uploads/`。判断当前模式：

```bash
curl -s http://127.0.0.1:8000/api/ontology/status | python3 -m json.tool
# mode = imported 即「导入的本体」；default 为预置领域；重启前不会自行变回 default

curl -s -X POST http://127.0.0.1:8000/api/domains/current/capabilities/query \
  -H "Content-Type: application/json" \
  -d '{"kind":"capability_match","params":{"task":"t_login_dev"}}'
# 导入态下领域能力返回 400「未声明能力……」，通用只读端点照常可用
```
