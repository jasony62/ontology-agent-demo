# 05 场景演练

一个完整用例：从启动到"智能体通过 MCP 使用本体"，覆盖全链路。

## 场景：上线"新功能"并核查合规

### 第 1 步：启动服务

```bash
docker compose up -d api mcp
curl -s http://127.0.0.1:8000/api/health | python3 -m json.tool   # status=ok
```

### 第 2 步：能力匹配——谁来做登录模块开发？

```bash
.venv/bin/python scripts/query.py capability_match --task t_login_dev --pretty
```

结论：`dev_agent`（研发Agent，已认证）具备 `Coding` 能力 → 匹配（规则 R1）。

### 第 3 步：任务编排——"新功能上线"如何拆解？

```bash
.venv/bin/python scripts/query.py orchestrate --task t_feature --pretty
```

结论：复合任务按依赖拓扑拆解为需求分析（req_agent）→ 编码 → 审查 → 测试 → 部署，逐环节匹配执行者。

### 第 4 步：分配 + 合规检测

```bash
.venv/bin/python scripts/query.py assign --task t_compliance_dev --agent junior_dev --pretty
```

结论：任务要求合规认证而初级研发 Agent 未认证 → **R4 合规冲突**被检出并给出可解释推导链。

### 第 5 步：图谱工作台编辑本体

打开 `http://127.0.0.1:8000`：用「显示推理全貌」查看推理结果 → 点图谱上的类 / 关系 / 个体，在右侧编辑框直接改（仅预览，刷新即丢、不写盘）→ 要落盘进「在线编辑」，改完点「覆盖当前本体文件」→ 图谱三档视图与右侧「图谱概览」统计自动刷新。

### 第 6 步：智能体接入（MCP）

豆包连接器新建自定义连接器 → HTTP + `http://127.0.0.1:9000/mcp` → 对话中直接问"谁能做登录模块开发？""为什么分配冲突？"，智能体调用本体推理工具返回确定性答案与推导链。

### 第 7 步：运维闭环

```bash
.venv/bin/python scripts/ontologyctl.py status      # 确认服务/本体/一致性
.venv/bin/python scripts/ontologyctl.py commit -m "本次演练变更"   # 变更入 git 并打 tag
bash scripts/backup.sh                              # 文件级快照备份
```

## 排查提示

| 现象 | 处理 |
|---|---|
| 领域推理返回"通用模式" | 服务已加载自定义本体，重启服务恢复默认本体（见 01 快速开始） |
| `--local` 报缺 owlrl/rdflib | 使用 `.venv/bin/python` 而非系统 python3 |
| MCP 连接器连不上 | 确认 `mcp_server.py` 已启动、URL 为 `http://127.0.0.1:9000/mcp` |
