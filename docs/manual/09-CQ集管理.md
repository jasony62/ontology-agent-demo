# 09 CQ 集管理

> CQ（Competency Question，能力问题）集用来回答：**这份本体承诺回答哪些问题、其中多少条已经定位到本体证据、上次回归是否可答。**
> 本页覆盖前端「CQ 集」页、REST 端点、`/mcp/cq` 工具，以及一条 CQ 的完整字段规格。

## 9.1 页面与标签的分工

前端页头有三个平级入口（#203 由 5 项收敛为 3 项）：

| 页面 | 看什么 | 典型问题 |
|---|---|---|
| **图谱工作台** | 本体结构：类 / 属性 / 个体 / 推理边 | 「这个类下面有哪些个体？」 |
| **当前领域** | 这个领域包能做什么：定位、能力、约束、示例题 | 「这套本体适合问什么？」 |
| **CQ 集** | 这份本体答得上什么：题库、覆盖率、回归、审计 | 「哪些能力问题有证据？上次回归过了吗？」 |

CQ 集页内有两个标签：

| 标签 | 看什么 | 典型问题 |
|---|---|---|
| **题目** | 题库总览、逐题增删改、审计、评估与导入导出 | 「这道题凭什么答得上？」 |
| **训练** | 上区题看板（题卡 + 阶段条 + 待决内嵌决策卡 + 待我处理 + 题卷下钻），下区全局事件（历史） | 「这道题走到哪了？要我做什么？当初怎么决的？」 |

时间线的类别筛选项是「全部 / 决策 / 观测·证据 / 回归 / 迭代 / 审计」；**迭代**不再是独立页面，按下后显示迭代档案卡片（业务话翻译 / 变更清单 / 闸门快照 / TTL 全文折叠）——「这轮 TTL 改动业务上意味着什么？」就在这里看。

题目页默认是**领导模式**（#210）：不出现 SPARQL 输入框与内部枚举，leader 只看业务语义与断言摘要，确认或驳回；需要直接改查询时显式切「专家模式」。训练页的决策卡带**现场上下文**（#211），并按「结论 / 依据来源 / 授权确认」结构化回收（#212）。

CQ 集页支持：总览看板（承诺 / 已定位 / 可答 / 缺口 + 两档覆盖率）、逐题增删改（题干 / 题型 / 状态 / 来源需求 / SPARQL 断言）、变更审计、运行评估、导入导出（JSON / cq-test YAML / JUnit）。

## 9.2 数据位置

```
data/workspaces/<ontology_id>/
├── cq_set.json            # 当前 CQ 集（本页的读写对象）
├── cq_set.audit.jsonl     # 追加式变更审计
├── runs/<ts>.json         # 每次回归的历史结果
└── metrics.jsonl          # 北极星事件（cq_evaluated_real 等）
```

- 预置领域：`ontology_id` 是领域名（如 `agent_task`），首次访问从领域包内 `cq_tests.json` 播种；
- 导入的本体：`ontology_id` 是工作区 uuid（如 `55d67fad72ef`），与 REST / MCP 共用同一身份；
- 这些文件都在 `data/` 下、**不被 `scripts/backup.sh` 覆盖**，备份方式见 [04 运维 · 备份](04-运维与本体管理.md#43-备份)。

## 9.3 一条 CQ 的字段规格

整集骨架：

```json
{
  "suite": "agent_task_cq_regression",
  "version": 2,
  "cases": []
}
```

题目合法字段共 8 个：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 稳定 id；缺省写入时自动分配 uuid |
| `cq` | **是** | 非空题干 |
| `expected_type` | 否 | 题型枚举；缺省补 `unknown`，填错 400 |
| `status` | 否 | 状态枚举；缺省补 `unset`，填错 400 |
| `requirement` | 否 | 来源需求标识（如 `REQ-1`） |
| `regression` | 否 | 回归断言，只允许 `{query, expect}`；留空则回归标 `not_tested` |
| `rule` | 否 | 退化定位用的规则标签（如 `R1` / `R3`） |
| `coverage_cache` | 否 | 最近一次回归回写的结论缓存，由系统维护 |

### 题型 `expected_type`

对齐 CQ4OE 基准：

| 值 | 中文 | 含义 |
|---|---|---|
| `retrieval` | 检索类 | 从图里取现成事实 |
| `derived` | 推导类 | 需要推理才有的结论 |
| `counting` | 计数类 | 期望一个数量 |
| `negative` | 反例类 | 期望「查不到」 |
| `unknown` | 未分型 | 合法兜底值；历史值 `set` 只读时显示为它，写入会被拒绝 |

> `derived` 与证明模块里的 `source=derived`（由推理产生而非断言）**同名不同义**，不要混用。

### 状态 `status`

`draft` 草稿 / `active` 启用 / `archived` 归档 / `unset` 缺失兜底。

### 回归断言 `regression{query, expect}`

`query` 必须是**非空 SPARQL**（SELECT 或 ASK，单一形态）。`expect` 支持裸 bool / 裸 int 简写，也支持显式判分对象：

| `expect.type` | 期望字段 | 语义 |
|---|---|---|
| `boolean` | `value`（布尔，默认 true） | 断言真假 |
| `exists` | `value`（布尔，默认 true） | 结果非空 / 为空 |
| `count` | `value`（整数） | 行数等于 N |
| `values` | `values`（数组） | 结果首列取值等于该数组 |
| `set_exact` | `values`（数组） | 结果首列集合精确相等 |
| `contains` | `values`（数组） | 结果首列包含全部期望值 |

完整示例：

```json
{
  "id": "T2-01",
  "cq": "哪些智能体可以执行「登录模块开发」？",
  "expected_type": "retrieval",
  "status": "active",
  "rule": "R1",
  "regression": {
    "query": "SELECT ?agent WHERE { ?agent <http://ontology.localhost/agent-task#can_execute> <http://ontology.localhost/agent-task#t_login_dev> }",
    "expect": {"type": "set_exact", "values": ["dev_agent", "junior_dev"]}
  }
}
```

## 9.4 已移除字段与迁移

0.8.3 起 CQ 只接受单一 SPARQL 断言（#179 / #180 / #181）。以下 7 个字段写入会得到定向 400：

| 旧字段 | 处理方式 |
|---|---|
| `tool` / `params` | 改为 `regression.query` + `regression.expect` |
| 平铺 `query` / `expect` | 移入 `regression` 对象内 |
| `anchor_terms` | 不再存储；定位由系统按题干自动计算（focus 模式仅在 `cq_author(draft=...)` 临时输入里用） |
| `priority` | 已移除 |
| `note` | 已移除；备注写进题干或 `requirement` |

示例错误：

```text
cases[0].tool：旧断言格式已移除：请改用 regression{query, expect}（#179）
cases[0].regression.expect.type 非法：'fuzzy'；合法值：boolean / exists / count / values / set_exact / contains
```

## 9.7 训练过程事件流

CQ 的训练过程不再散落在会话记忆里，而是**只追加**到 `data/workspaces/<id>/training_log.jsonl`。每行恰好六个顶层键：

```json
{"ts":"2026-11-15T00:00:00+00:00","event":"decision_asked",
 "ontology_id":"agent_task","actor_type":"human","actor":"web",
 "content":{"decision_id":"d-...","kind":"expectation","question":"...","options":["A","B"],
            "recommended":"A","reason":"...","background":"...","event_id":"..."}}
```

- 时间由服务端生成；`content` 整体收在一个对象里，不能覆盖时间 / 事件名；
- 事件分两族：**状态翻转族**（`decision_asked` / `feedback_received` / `decision_resolved_by_self` / `intent_pending_marked`）只能经 `cq_decision` 写入；**观测证据族**（出题 / 放行 / 回归 / 闸门 / 证据 / 迭代 / 熔断 / 归因）可经 `cq_training_write` 写入；
- 未知事件、缺必填、类型错、额外字段、题目不存在 → `invalid_event`，**不落盘**；
- 并发靠单行追加，不引入锁；坏行读取时跳过。

题目定义仍以 `cq_set.json` 为权威。网页建题 / 发题会补写 `case_authored` / `case_released` 留痕（操作者 `human/web`），MCP 路径为 `agent/mcp`；其余增删改仍只进审计，不写训练事件流。`summary.pending_decisions` 与 `cases[].intent_pending` 是**读接口层合并的视图字段**，直接读原始 `cq_set.json` 看不到。

## 9.8 决策入口与反馈

`/mcp/cq` 的 `cq_decision` 是唯一入口，动作固定三个：

| 动作 | 用途 | 必填 |
|---|---|---|
| `ask` | 提问（P0） | 类别（五类）、问题、选项 ≥2、推荐项（属于选项）、推荐理由、背景话术 |
| `feedback` | 反馈（P0 / P2） | 决策编号；反馈原文 / 所选选项 / 跟进对象 / 结构化结论 / 依据来源 / 授权确认可任意组合，**可全空** |
| `withdraw` | 自答撤问（P1，仅智能体侧） | 决策编号、自答方法 |

五类决策固定 `semantic / expectation / priority / term / scope`，不允许自定义。反馈**不设状态参数**：服务端只记一条 `feedback_received`，状态由读时投影判定——有可采纳结论 → 已裁决；无结论 → 待跟进；`decision_resolved_by_self` → 已撤回。回答来源由通道注入（REST `direct` / MCP `agent_relay`），调用方不可覆盖。

`feedback` 的结构化字段（#212）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `conclusion` | `adopt` / `reject` / `defer` | 采纳推荐 / 驳回或改选 / 暂缓；`defer` 或未授权 → 待跟进 |
| `basis` | `self` / `expert` | 自己判断 / 已问他人确认（人名放 `follow_up_with`） |
| `authorized` | 布尔 | 是否确认可以按此决策执行；`false` → 待跟进 |

缺省这三个字段时沿用旧口径（有选项或原文即裁决），保证旧脚本兼容。

## 9.9 现场、缺口与时间线

- `cq_resume`：状态摘要、上次回归、待决、待跟进、熔断、迭代引用、按题目聚合的意图标记 + 决策议程 + `context_gaps` + `next_suggested`；默认 `snapshot`，`full` 附历史。实时聚合，不落快照。
- `cq_agenda`：从 CQ 集现场生成待决议程，覆盖未锚定题 / 质检问题 / 回归失败 / 覆盖缺口 / 冗余；每条含业务话 `background / question / options / recommended / reason`，编号按「类别 + 题号」稳定生成。只读、不落盘；前端只消费 `cq_resume` 合并后的 `pending_decisions`，不自行扫描 CQ 状态。
- 议程在第一次被回答时才惰性物化为一条 `decision_asked` 事件（归属智能体），因此读接口保持纯读，历史仍可追溯；同一「类别 + 题号」不会重复出题。
- 文案口径（#208）：生成侧不写事件类型名 / 内部路径 / SPARQL 片段；前端 `plainCopy` 对决策背景、问题、选项、推荐理由、缺口与下一步做兜底去黑话；决策编号、类别与原始字段默认收进「展开看技术细节」，专家点开才显示。
- 缺口规则 G1–G6：回归失败无归因、迭代缺业务话、待跟进超期、熔断未生成决策、迭代档案缺失、反馈无任何可采纳内容。G6 只提示不阻断。
- `cq_timeline`：训练事件 + 审计 + 回归历史 + 迭代档案四源聚合，支持 `since / kinds / limit`；时间取自文件内容，不解析文件名。
- `cq_iteration_write`：写 `iterations/<id>.json`（业务话翻译 / 变更清单 / 闸门快照 / TTL），并连带记 `iteration_started / gate_result / iteration_applied / iteration_accepted`。

## 9.11 角色模型与北极星护栏指标（#206）

协同主线的角色边界只有一句话：**人担决策责任，智能体扛专业活**。

| 角色 | 只做 | 不做 |
|---|---|---|
| 人（leader） | 在 Web UI 看现场、读议程、逐条「采纳推荐 / 改选 / 暂缓」，必要时写「已线下找谁确认」 | 不写 SPARQL、不构造断言、不切本体内部状态、不补术语、不创作题目、不输入自然语言意图 |
| 智能体 | 经 MCP 出题 / 定位 / 质检 / 回归 / 议程；按人的决策落库、换路径、固化断言、导出 CI | 不替人拍板；不在后端做第二套独立自动机 |

闭环五步（硬约束，任何改造都不得让它模糊）：

1. 智能体驱动人：主动产出并推送待决事项，人不必自己发现该决什么；
2. 智能体经 MCP 生成数据：定位 / 质检 / 可答 / 缺口 / 建议题 / 议程全经 MCP 工具生成；
3. 人经 Web UI 看数据做决策：只在 Web UI 消费数据、给决策；
4. 智能体看人的决策进行下一步行动：采纳 → 落库 / 执行，驳回 → 换路径，确认预期 → 固化断言，锁定 → 导出 CI；
5. 新状态回到第 2 步，形成循环。

### 指标树（领导模型下仍全部保留）

- **质量驱动 5 条**：锚定 / 可答 / 质检 / 覆盖 / 去冗；
- **协作效率 4 条**：采纳率 / 往返轮次 / 自动修复率 / 决策时延——议程直接给选项，往返轮次与决策时延反而更顺；
- **其余护栏**：留存率 / 工具报错率 / cq-test 纳入 CI 率。

### 两条新增护栏（把「主动告知」量化）

| 指标 | 定义 | 目标 |
|---|---|---|
| 决策面填充率 | 打开工作台时，系统主动呈现 ≥1 条可决事项的会话占比 | ≥90% |
| 主动决策议程覆盖率 | 自动生成的待决决策 / 应被提出的决策总数 | 逐步逼近 100% |

口径说明：

- 「可决事项」= `cq_resume.pending_decisions` 非空（智能体经 `cq_decision ask` 提出的 + `cq_agenda` 从现场推导并经 `resume` 合并的）；
- 采集随 P0 改造落地（本版先定义口径）；指标要求的是系统先开口，而不是让人自己发现问题；
- 工作区里的北极星 / 功能评估 / 系统改进方案三份文档与本页共用同一口径；本页是仓库内的口径基线，外部文档更新时以相同定义为准。

## 9.12 领导模式与结构化决策回收（#210–#212）

### 题目页：领导模式默认，专家模式显式切换

- **领导模式（默认）**：不显示 SPARQL query / expect，也不显示 `expected_type` / `status` 下拉；leader 只看到题干、业务语义（检索 / 推导 / 计数 / 反例）和一句断言摘要（「应判定为是」「应正好查到 3 条」「结果应包含：…」）。
- **确认 / 驳回**：确认后，有断言 → 状态自动置为启用；无断言 → 保持草稿并提示「等智能体补断言」。驳回 → 退回草稿，等智能体调整。两种动作都不要求 leader 写查询。
- **专家模式**：显式切换后才出现 SPARQL 与内部枚举，保留给真专家核对；切回领导模式即隐藏。
- 断言摘要由读视图字段 `assertion_summary` 提供（不落盘），MCP 与 REST 读到的是同一句业务话。

### 决策卡：现场上下文自包含（#211）

- 议程生成的每条决策卡带 `context`，用业务话说明「为什么问、这题现在卡在哪」，例如：「这题能对上本体里的『登录模块开发』，目前查到 6 条证据。上次回归没通过：实际结果和预期不一致。」
- 智能体经 `cq_decision ask` 也可传 `context`；前端卡片直接展示，不需要 leader 跳到题目页读 SPARQL。
- 原始编号 / 类别 / 背景 / 上下文仍收在「展开看技术细节」，默认收起。

### 结构化回收决策结果（#212）

- 决策卡按「结论（采纳 / 驳回改选 / 暂缓）→ 依据来源（自己判断 / 已问他人）→ 授权确认」回收，用户必须勾选授权后才能提交；选推荐项默认 `adopt`，选其他项记 `reject`，另设「暂缓」按钮。
- 结构化字段填充率直接用 `cq_resume.counts.structured_feedback / counts.feedback` 口径计算（三项齐全才计入），无需另建埋点。
- 回归失败 / 覆盖缺口自动框成决策卡：失败题给「改预期以匹配新结果 / 补本体后保持原预期 / 删除该题」三选一；**回归失败不占议程名额，100% 出卡**。
- 时间线保留结构化回执：结论、依据来源、是否授权；`withdraw` / 自答方法等实现词不再出现在 leader UI，统一显示为「该项已由智能体自行处理」。

## 9.13 题干提及覆盖（只读，#215）

用于回答「哪些类/属性从来没有被任何 CQ 题干提到」——不是「解答依赖哪些公理」：

- **口径**：元素全集 = 本体领域类 + 属性；「提及」= `cq_locate` 锚点与元素 label / 短名精确匹配。只认字面，同义、简称、隐含依赖会漏。
- **输出**：`summary`（题数 / 元素数 / 已提及 / 未提及 / 提及覆盖率 / 定位失败数）、`elements`（每个类/属性的 `case_ids`）、`uncovered`、`unmatched_anchors`（个体 / 枚举 / 分词锚点，不冒充类/属性）。
- **入口**：`GET /api/domains/current/cq/coverage` 与 MCP `cq_coverage`；前端在「专家模式 → 质量盲区（题干提及）」按需检查，领导模式不出现。
- **边界**：不落盘、不改 CQ / 训练 / 议程；不做公理级 provenance（#216 / #159-B），也不做多集（#217 / #159-C）。

## 9.14 题生命周期看板（#219）

训练标签从「按决策状态分块的日志面板」改为「以题为主语的看板」：

- **题卡是主语**：每题一张卡，显示当前阶段（已建题 / 回归中 / 待我决 / 已决 / 修复中 / 通过 / 待跟进）、阶段条与最近回归。
- **概览按题 roll-up**：待决 / 已决 / 待跟进都按题数，决策条数并列显示；点数字可筛题卡，熔断独立。
- **待我处理**：从「待决题」直达，只显示待决题，首题答题卡直接展开；提交后自动定位下一题，授权勾选保留。
- **这道题的卷**：题卡按钮 / 阶段条分段 / 答题中回看三个入口；事件按时间正序，支持主体（人 / 智能体 / 系统）与阶段双筛，人裁决高亮，技术细节折叠。
- **全局事件**：整轮跑分 / 整库保存 / 迭代归档放在下方「全局事件（历史）」，不再与单题轨迹混排；带涉及题的下钻入口。
- **数据来源**：`cq_resume` 新增 `resolved_decisions` 与 `lifecycle`（题卡投影）；`GET /cq/cases/{case_id}/events` 提供单题卷；R7 让网页建题 / 发题补写 `case_authored` / `case_released`，操作者为 `human/web`。
- **边界**：不改题库管理状态（草稿 / 启用 / 归档 / 未分型）；训练阶段是另一套词，两者不合并。事件流只追加、不迁移老数据、不做投影缓存。
