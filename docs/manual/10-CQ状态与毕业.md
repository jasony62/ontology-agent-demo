# 10 CQ 状态与毕业

> 本页是 CQ 题目**状态怎么流转、什么时候算毕业**的唯一说明。文档其它位置若与这里冲突，以本页为准。
>
> 对应实现：`cq/graduation.py`（毕业判定）、`cq/cq_store.py`（写入与审核重置）、`cq/lifecycle.py`（看板投影）。

## 10.1 三组状态，不要混在一起

一道题同时带着三组信息，它们各自回答不同的问题：

| 维度 | 字段 | 取值 | 回答的问题 | 谁维护 |
|---|---|---|---|---|
| 运营态 | `status` | 草稿 `draft` / 启用 `active` / 归档 `archived` / 未分型 `unset` | 这一版现在能不能拿去用？ | 人在编辑弹窗里选 |
| 治理态 | `review.state` | 未要求 `none` / 待审核 `pending` / 已通过 `approved` / 已驳回 `rejected` | 这一版有没有人看过并留下结论？ | 审核流程 |
| 判定结果 | `graduated` | 是 / 否（读时计算，不落盘） | 这一版是否满足全部毕业条件？ | 系统按下面规则算 |

关键区别：

- **运营态是人的承诺**：启用 = 这一版**验证过且审过**。草稿即使质量全过，也不能毕业。
- **治理态是留痕**：待审核**不阻断毕业**；审核状态只在详情区「审核」组显示，不进「缺：…」列表。
- **判定结果是派生值**：没有单独字段可改，永远由运营态 + 五项质量条件算出来。

## 10.2 状态图

```text
                      运营态 status
        ┌──────────┐  人选「启用」+ 保存   ┌──────────┐
        │  draft   │ ───────────────────▶ │  active  │
        │  草稿    │ ◀─────────────────── │  启用    │
        └──────────┘  人选「草稿」/        └──────────┘
             │        实质变更自动退回          │
             │  归档                            │  归档
             ▼                                 ▼
        ┌──────────────────────────────────────────┐
        │              archived 归档                │
        └──────────────────────────────────────────┘

                      治理态 review.state（仅 required=true 时有意义）
        none / 未要求 ──要求审核──▶ pending 待审核 ──人通过──▶ approved 已通过
              ▲                         │                        │
              └────────── 驳回 ◀────────┴────── rejected 已驳回 ─┘
                                    （可重新提交）

                      判定结果 graduated（读时计算）
        graduated = (status == active) AND (blockers == [])
```

### 迁移触发者与条件

| 迁移 | 触发者 | 条件 / 后果 |
|---|---|---|
| 草稿 → 启用 | 人（编辑弹窗「题库状态」选启用 + 保存） | 必审未过（`required=true` 且 `state != approved`）时拒绝，返回 `review_pending` |
| 启用 → 草稿 | 人（「退回草稿」或下拉选草稿） | 只改运营态，不通知智能体 |
| 启用 → 草稿 + 待审核 | 系统（实质变更） | 题干 `cq` 或断言 `regression` 内容变化，且原审核已通过；两字段**同一写入路径**原子更新，不留 `active + pending` 中间态 |
| 任意 → 归档 | 人 | 归档后一律不毕业；已有审核通过痕迹保留 |
| 归档 → 草稿 / 启用 | 人 | 需重新满足审核门与质量条件 |
| 待审核 → 已通过 | 审核人 | 必审题的唯一放行路径 |
| 待审核 / 未要求 / 已通过 → 已驳回 | 审核人 | 驳回题不参与回归（不进分母） |

## 10.3 毕业条件（题目级）

**毕业 = 运营态为启用，且以下五项全部满足**：

| # | 条件 | 不满足时的 blocker | 说明 |
|---|---|---|---|
| 1 | 已锚定 | 未锚定 | 题干能对上本体术语，并且查得到证据 |
| 2 | 已分型 | 未分型 | 题型不是 `unknown` |
| 3 | 有断言 | 缺断言 | 存在 `regression` |
| 4 | 回归通过 | 未通过 | 有断言，且上次回归结论 > 0 |
| 5 | 未归档 | 已归档 | 运营态不是归档 |

两条容易误读的规则：

- **「缺断言」与「未通过」互斥**。没有断言时只挂「缺断言」；只有“有断言但结论 ≤ 0”才挂「未通过」。
- **「未启用」不是 blocker**。它是运营态门槛，只在列表「缺：…」里提示人去编辑弹窗翻批；质量 blocker 始终是上面五项。

题集级另有「交付线 / 可交付」：`目标题量` 由本体规模估算（关键术语数 × 0.5，最低 20），所有题毕业才算可交付。题目级叫「毕业条件」，题集级叫「交付线」，避免「这道题交付了 / 这套题交付了」混在一起。

## 10.4 合法组合与禁止组合

| 组合 | 结论 | 原因 |
|---|---|---|
| 草稿 + 已通过 + 已毕业 | **禁止** | 草稿不能毕业；审核通过只说明治理留痕 |
| 启用 + 待审核 + 已毕业 | **允许** | 待审核不阻断毕业（首次待审、未发生实质变更） |
| 启用 + 已通过 + 已毕业 | 允许 | 五项质量全过 |
| 归档 + 已通过 | 允许，但不毕业 | 允许保留历史审核痕迹；「已归档」是 blocker |
| 断言改了，`review.state` 仍已通过 | **禁止** | 实质变更自动重置为待审核，并把启用退回草稿 |
| 启用 + 缺断言 + 已毕业 | 禁止 | 「缺断言」是 blocker |
| 无断言 + 「未通过」同时在列 | 禁止 | 两条互斥，只挂更具体的「缺断言」 |

## 10.5 不变量清单（可直接映射到代码）

| 不变量 | 落点 |
|---|---|
| `graduated == (status == "active" and blockers == [])` | `cq/graduation.py::is_graduated` |
| `blockers` 固定五项，顺序固定；「待审核」永不进 blockers | `cq/graduation.py::BLOCKERS` / `case_blockers` |
| `status == "archived"` ⇒ 不毕业 | `case_blockers` 追加「已归档」+ `is_active` 门槛 |
| 无断言 ⇒ 只挂「缺断言」，不挂「未通过」 | `case_blockers` 的 `if not regression / elif not answerable` |
| 读视图、生命周期看板、交付判定、CQM、评审包用同一个毕业数 | `build_view` / `build_lifecycle` 共用 `graduation_view` |
| 实质变更且原审核已通过 ⇒ `review.state = pending` 且 `status = draft`，同一写入路径 | `cq_store._apply_review_reset` |
| 写入结果不得出现「启用 + 必审未过」（存量祖父条款除外） | `cq_store._review_gate` |
| 删除时刻的毕业快照只服务留存率，不参与交付判定 | `cq_store.graduated_snapshot`（注释已标明） |

> `graduated_snapshot` 是审计口径：删除时只读集内字段，没有当次锚点复核。它**不得**被拿来算 CQM、交付线或列表状态。

## 10.6 一个具体例子

一道题原本「启用 + 已通过」，五项质量全过，因此毕业。此时人修改了它的断言：

1. 系统比较 `regression.query/expect`，发现实质变更；
2. 同一写入里把 `review.state` 重置为 `pending`，清空审核人 / 时间；
3. 同时把 `status` 从 `active` 改为 `draft`；
4. 页面下一次读取：`graduated = false`，列表显示「缺：未启用」；
5. 人重新审核通过后，在编辑弹窗选「启用 + 保存」，再次满足五项质量条件，才重新毕业。

只改来源需求、题型、备注等元数据不会触发第 2–3 步，题目保持启用与已通过。
