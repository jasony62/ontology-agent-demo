# 06 二次开发指南

面向"想扩展系统"的开发者：新增领域、换本体、扩展工具。核心思想：**通用引擎 + 领域适配器分离**——引擎不含任何领域词汇，领域语义全部外置在 `domains/` 领域包，运行时约定式发现（`domains/registry.py`）。

## 6.1 架构速览

```text
reasoner/engine.py       通用 OWL 2 RL 引擎（加载/推理/SPARQL/查询，无领域词汇）
reasoner/{derivation,proof,semantic}.py   推导链 / 结构化证明 / 语义配置
domains/registry.py      领域包约定式注册表（list_domains / load_domain）
domains/<name>/          一个领域一个包（插件式）
  ├─ NAME / DESCRIPTION / create_adapter(engine, config=None)   # 必须暴露
  ├─ config.json          语义配置（类名/属性名映射 + 推导链展开规则）
  ├─ derivation.json      推导链说明
  ├─ access_policy.json   语义白名单（受控语义接口）
  ├─ guard_config.json    调用护栏配置（预算/循环/缓存/审计，默认关闭）
  ├─ gates_smoke.json     pipeline_gate G3 物化冒烟断言集
  ├─ cq.py / cq_prompts.json         CQ 工位接线（实现在 ontology_plugin_sdk/cq/）/ 提示词
  ├─ cq_tests.json（可选题库：存在时用于查重，缺失则跳过）
  ├─ adapter.py           领域查询实现（capability_match 等）
  ├─ mcp.py               MCP 工具注册（可选）
  └─ *.owl                该领域本体
```

## 6.2 新增一个领域（四步）

**第 1 步：准备本体**。编写或复用 OWL 文件，如 `domains/my_domain/my_domain.owl`。

**第 2 步：建领域包**。`domains/my_domain/__init__.py` 暴露三要素：

```python
NAME = "my_domain"                                    # 领域标识
DESCRIPTION = "我的领域：……"                          # 展示给智能体/用户
CAPABILITIES = ("capability_match", "graph_export")   # 声明即承诺：清单内必须实现
PLUGIN_API = "1"                                      # 按哪一版插件 API 编写

from ontology_plugin_sdk import PluginContext         # 领域包的唯一入口

def create_adapter_ctx(ctx: PluginContext):
    """把通用引擎包装为该领域的查询语义"""
    from .adapter import MyAdapter
    cfg = ctx.load_domain_config(ctx.path("config.json"))
    return MyAdapter(ctx.engine, cfg, ctx=ctx)
```

> **声明即承诺有两半**：`CAPABILITIES` 说"我有什么"，`CAPABILITY_HANDLERS` 说"从哪进来"。
> `CAPABILITIES` 里框架没预见的名字（如 `diagnose`）必须有落点，否则加载即拒：契约方法 /
> `CAPABILITY_HANDLERS` 处理器 / 适配器同名方法三者之一（只走 MCP 的领域属最后一种）。
> 想让它也能从 REST 触达，注册处理器即可，签名 `(adapter, request) -> dict`，参数取自
> `request.params`，抛 `ValueError` 会被转成 400——详见[扩展新领域](../guide/08-扩展新领域.md)。
>
> **导入纪律**：领域包只 import `ontology_plugin_sdk`（领域插件 SDK：契约 / 语义配置 /
> 推导链 / ABox / 上下文 / 引擎原语 / CQ 工位）与 `rdflib`；不要 import `reasoner.engine` /
> `reasoner.semantic` 等宿主内部模块——框架挪实现时领域会跟着碎。
> 这条纪律由 `tests/test_plugin.py` 的 ast 扫描断言守住，且**不存在白名单**：连工具接线层
> （`mcp.py` / `cq.py`）也不许碰宿主模块。CQ 曾经是唯一的例外，P4 收尾时搬进了
> `ontology_plugin_sdk.cq`，现在 `reasoner.*` 在领域包里出现即测试失败。
> 老写法 `create_adapter(engine, config=None)` 仍可用，加载器会自动回退。
> 不写 `PLUGIN_API` 不会报错，但也就失去了版本冲突的早期预警——不匹配时加载器直接
> 拒绝加载，而不是等到某个请求进来才 `AttributeError`。

**第 3 步：语义配置**（`config.json`）。把领域查询依赖的类名/属性名外置，换同构本体时可整体覆盖：

```json
{"semantic": {"agent_class": "Agent", "task_class": "Task",
  "has_capability": "has_capability", "requires_capability": "required_by"}}
```

**第 4 步：注册并验证**。约定式发现，无需改注册表代码：

```python
from domains import list_domains, load_domain
list_domains()                                # 自动发现 my_domain
adapter = load_domain("my_domain", engine)    # 加载并调用领域查询
```

领域查询函数签名遵循默认领域（见 `domains/agent_task/adapter.py`：capability_match / orchestrate / assign / classify / consistency / explain 等），返回结构与推导链一致。

### 6.2.1 多领域与热切换

领域包只在**运行态 root** 下生效（`domains/`，已 gitignore）。安装是唯一入口：

```bash
python scripts/ontologyctl.py domain install --from ./examples/agent_task
```

运行起来之后，当前领域是**可切换**的（REST API 无需重启）：

| 端点 | 作用 | 适用 |
|---|---|---|
| `GET /api/domains` | 已安装领域 + 当前领域 + 模式 | 前端领域下拉 / 运维排查 |
| `POST /api/domains/reload` | L2：重读领域代码 + 重建引擎 | 改了 `adapter.py` / `config.json` |
| `POST /api/domains/{name}/activate` | L3：切到另一个已安装领域 | 多领域切换 |
| `POST /api/ontology/reload` | L1：只重载 `.owl` 与 `extensions/` | 改了本体内容 |

```bash
curl -X POST http://127.0.0.1:8000/api/domains/agent_task/activate
curl http://127.0.0.1:8000/api/health | jq .domain
```

失败的语义值得单独说清：**切换先构造、后替换**。新领域加载失败（不存在 / 契约不满足 /
本体打不开）一律返回 400，**旧领域继续服务**——宁可让一次切换失败，也不能让服务停在半个领域上。

MCP 侧是**显式不做的**：工具清单在启动时注册进 server，换领域等于 tool schema 变化，
客户端必须重新协商 `tools/list`。所以 MCP 换领域 = 重启进程（`--domain` 读配置默认值），
不要在事件循环里热替换 MCPServer 实例。

## 6.3 扩展 MCP 工具

领域包内 `mcp.py` 用 `server.tool` 注册领域工具（默认领域 14 个：能力匹配/编排/分配/分类/一致性/图谱/实体/状态/CQ 建模两件套/SHACL 体检/CQ 出题两件套）；通用工具（SPARQL/个体/类/类型/属性/重推理/证明/策略/时序/护栏状态/质量门禁）在 `mcp/mcp_server.py` 注册，与领域无关。新增领域工具 = 在 `domains/<name>/mcp.py` 增加 `@server.tool` 函数并调用适配器方法。

**护栏自动生效**：通用工具经 `mcp/tool_guard.py` 的 `wrap_server_tool` 注册管道统一包装——`guard_config.json` 启用后自动获得预算熔断/循环拦截/缓存/审计；领域工具如需护栏，可在领域包注册时走同一包装器。

## 6.4 建模流水线：质量门禁（G1–G4）

**核心工具 `pipeline_gate(ttl, abox?, gates?)`**（MCP 通用工具，`reasoner/pipeline_gate.py`）把建模草稿按四道闸门 fail-fast 过闸，废品不出车间：

| 闸门 | 检查 | 打回方向 |
|---|---|---|
| G1 DL 格式 | 防 OWL-Full（owlready2 `is_owl_full()` + 结构断言）；数据属性 inverse functional 主键陷阱拦截 | 回 S2 |
| G2 一致性 | owlrl 物化 + Nothing/disjointWith 矛盾检查 + 空类提示（HermiT 可选增强，未启用 `mode=degraded` 显式标注） | 回 S2 |
| G3 物化冒烟 | 领域 `gates_smoke.json` 断言集（预期谓词 min_count，如 `can_execute ≥1`）；断言集为空如实 skipped | 检查骨架 |
| G4 SHACL | 复用 pyshacl + `包内 shapes/<domain>.ttl`，violations 短名化透传 | 修数据字典或 SHACL |

实测（默认本体 TTL）：

```bash
.venv/bin/python -c "
from reasoner.engine import ONTO_PATH, OntologyEngine
from reasoner import pipeline_gate
e = OntologyEngine(ONTO_PATH)
r = pipeline_gate.run_gates(e.raw.serialize(format='turtle'))
print(r['overall'], r['failed_at'], r['next'])   # pass None S4 查询暴露（四道闸门全部通过）
"
```

- 遇 fail 即停（后续闸门标 `not_run`），`failed_at` 定位卡闸位置；每闸输出 `{status, evidence, remediation}`；
- `gates` 参数支持单闸调试（如 `['G3']`），空列表全部 skipped（非假通过）；只读（拷贝图物化，不写回主图）；
- 术语/结构层校验对应 `validate_tbox_draft` 的 L1–L5，与闸门互补。

**SHACL 形状**：`包内 shapes/<domain>.ttl` 供 G4 与 `validate_shapes` 工具使用。结合 `docs/MODELING_PIPELINE.md`、`docs/DOMAIN_PACKAGE_GENERATION.md`（从 OWL + 业务知识库自动生成领域包：能力分层表、规则.md、术语表.md、场景.md）可半自动化落地新领域，过闸后再进入查询暴露。

## 6.5 扩展通用查询 / 新规则

- 通用查询（SPARQL/个体/类/类型/属性/重推理）在 `reasoner/engine.py`，与本体无关；
- 业务规则 R1/R3 表达为 OWL 公理（属性链 / 传递属性），由 owlrl 自动推理；R2（组合委派）/R4（合规冲突）实现在领域适配器 `domains/agent_task/adapter.py`（**不是** `reasoner/engine.py`）——R2 的组合语义 OWL 2 DL 本就能表达，项目为保持 .owl 简洁用代码生成、R4 为运行时校验，属工程权衡而非语言限制；
- 新增规则建议先在 `reasoner/` 实现并加测试（`tests/`），再在适配器与文档中同步。
