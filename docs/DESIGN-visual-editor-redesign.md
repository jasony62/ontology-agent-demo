# 可视化编辑器（Designer）UI 改版设计方案

- 项目：本体智能体协作系统 · 前端工作台「可视化编辑」面板
- 版本：方案 v1（已评审定稿 · 2026-10-27，实施分支 feat/designer-ui-redesign）
- 日期：2026-10-27

---

## 1. 现状问题盘点（对照当前 Designer.tsx / index.css）

| # | 问题 | 现状证据 | 影响 |
|---|---|---|---|
| P1 | 布局无主次、无信息架构 | 三栏 `auto-fit` 平铺（实体/属性/关系），编辑表单挤在列表下方，随选中项"伸缩跳动" | 用户找不到"在哪编辑"，误以为不可编辑 |
| P2 | 表单控件零样式 | `input`/`select` 无全局样式（仅 OntologyEditor 的 `.ef-field` 有局部样式）；`button` 裸默认外观；`.secondary` 仅在 `.toolbar` 作用域内生效，Designer 内按钮"样式失效" | 控件观感停留在浏览器默认，无品牌、无状态反馈 |
| P3 | 无状态反馈 | 列表项选中仅 `fontWeight` 变化；无 hover 态；按钮无 disabled/loading 视觉 | 可点击性不明，操作无确认感 |
| P4 | 校验脱离上下文 | 校验全部集中在面板顶部（已分组），字段旁无内联错误，改错需"先看上面再回头找" | 修改体验割裂 |
| P5 | 危险操作裸奔 | 「删」为文字小按钮，无二次确认、无 hover 警示色 | 误删风险高 |
| P6 | 空态/引导缺失 | 未选中实体时一行灰字"先选择实体"；无新增后的聚焦引导 | 新手无从下手 |
| P7 | 无设计 token | 色板/字号/间距散落内联 style，无统一规范 | 后续维护成本高，观感不一致 |

## 2. 设计目标与参照基准

**目标**：把可视化编辑从"能用的原型"提升到"可交付的编辑工作台"——信息架构清晰（资源列表 ⇄ 详情编辑分离）、控件状态完备（hover/focus/disabled/error）、危险操作有护栏、空态有引导。

**参照基准**（互联网主流标准）：
- 布局与表单组织：Ant Design 表单规范（Label 左对齐 / 字段分组 / 内联校验）、Linear / Notion 的"左列资源树 + 右列详情编辑"模式
- 控件规范：Material Design 组件状态矩阵（默认/hover/focus/disabled/error）、shadcn/ui 的表单字段（label + 控件 + 校验文案层级）
- 视觉：现代 SaaS 浅色主题（白卡片 + 浅灰底 + 单一主色 + 语义色点缀），8px 间距网格

**设计原则（4 条）**：
1. **选中即编辑**：点列表项 → 右侧详情区变为可编辑表单，列表不因编辑"伸缩跳动"
2. **错误靠得近**：字段级内联校验为主、面板级分组摘要为辅
3. **危险可撤销**：删除一律二次确认；新增自动聚焦
4. **状态可见**：每个可交互元素都有 hover/focus/selected/disabled 明确状态

## 3. 布局方案（信息架构）

```
┌─────────────────────────────────────────────────────────────┐
│ 工具栏：标题 · 校验摘要徽标(可折叠展开) · [重置](放弃未保存改动)     │
├──────────────────────────┬──────────────────────────────────┤
│ 左侧 资源列表（1/3 宽）      │ 右侧 详情编辑区（2/3 宽）              │
│ ┌ 实体类型（N） 搜索🔍 [＋] ┐ │ ┌ 空态/选中态卡片                      │
│ │ ▸ 类卡片（图标 名称 id）   │ │ │ 基本信息：id / 名称 / 描述 / 图标 / 色 │
│ │ ▸ ...（hover 高亮、选中     │ │ │ 字段组：标识属性🔑 属性列表（增删改） │
│ │   高亮 + 右侧"编辑"入口）  │ │ └──────────────────────────────────┘ │
│ └───────────────────────┘ │ ┌ 关系（选中关系时）                  │
│ ┌ 关系（M） 搜索🔍 [＋]     │ │ │ 名称 / from / to / 基数 / 描述       │
│ │ ▸ 关系卡片（hover/选中）    │ │ └──────────────────────────────────┘ │
│ └───────────────────────┘ │                                  │
├──────────────────────────┴──────────────────────────────────┤
│ 折叠式校验面板（阻断 / 必改 / 建议，默认收起摘要，有阻断自动展开）      │
└─────────────────────────────────────────────────────────────┘
```

要点：
- **左列**：实体与关系分两个分组（各带数量徽标、搜索框、新增按钮）；列表项为"卡片行"（图标 + 名称 + id 短标签），hover 背景微亮，选中主色左边条 + 浅色底。
- **右列**：随选中项切换——选中实体 → 实体详情卡片；选中关系 → 关系详情卡片；未选中 → 引导空态（图示性文案 + 三个快捷按钮：新增实体 / 新增关系 / 导入本体）。属性编辑内嵌在实体详情卡片中，不再独立成列。
- **校验面板**：固定在面板底部，可折叠；条目与顶部现状一致（#22 分组逻辑保留），字段级错误同时内联显示在对应输入框下方。

## 4. 组件与样式规范（设计 token）

### 4.1 色板（沿用并扩展现有语义）

| Token | 值 | 用途 |
|---|---|---|
| `--primary` | `#0078d4` | 主按钮、选中态、焦点环、链接 |
| `--primary-soft` | `#eaf1fb` | 选中行背景、hover 底色 |
| `--danger` | `#d83b01` | 删除、阻断级错误 |
| `--success` | `#107c10` | 成功、已保存 |
| `--warning` | `#b06000` | 建议级提示 |
| `--text` / `--muted` | `#1a1a2e` / `#5a6b7f` | 正文 / 次级 |
| `--bg` / `--panel` / `--border` | `#f3f5f7` / `#fff` / `#dde5f0` | 页面/卡片/描边 |
| `--danger-bg` / `--danger-border` | `#fdf3f3` / `#e3b0b0` | 错误底色 |

### 4.2 按钮变体（全局统一，替代裸 `<button>`）

| 变体 | 样式 | 状态 |
|---|---|---|
| 主按钮 `.btn` | 主色底白字、圆角 6、高 32px、字号 13 | hover 加深 5%、active 下压 1px、disabled 45% 透明度 + not-allowed |
| 次按钮 `.btn.secondary` | 白底 + 边框 + 主色文字 | hover 主色浅底 |
| 危险按钮 `.btn.danger` | 白底 + 红字 + 红边框（轻量态） | hover 红浅底 |
| 文字/图标按钮 `.btn.ghost` | 无底色、图标 + 文字 | hover 灰底（用于「删」「编辑」小操作） |
| 图标按钮 `.btn.icon` | 仅图标、固定 28px 方块 | 带 title 提示 |

### 4.3 表单字段（统一 `.field` 结构：label + 控件 + 辅助/错误文案）

- 结构：`label（11px muted，必填带 *）→ input/select（高 30px、圆角 6、边框 #dde5f0）→ 下方 11px 辅助文案或错误文案（红色）`
- 状态矩阵：默认（灰边框）/ focus（主色 2px 焦点环 + 圆角）/ hover（边框加深）/ disabled（灰底）/ error（红边框 + 下方红字）
- 控件统一：`input`、`select`、`textarea` 同一高度体系；`select` 带自定义下拉箭头（`appearance: none` + 背景箭头）

### 4.4 间距 / 字号 / 圆角

- 间距网格：4 / 8 / 12 / 16 / 24（面板内统一 12~16）
- 字号层级：12（辅助/标签）/ 13（正文控件）/ 14（区块标题）/ 15（面板标题）
- 圆角：卡片 10、内嵌块 8、控件 6
- 阴影：卡片 `0 1px 4px rgba(0,0,0,.06)`，弹层 `0 8px 24px rgba(0,0,0,.12)`

## 5. 交互细节（用户友好性）

| 场景 | 行为设计 |
|---|---|
| 新增实体/关系 | 列表尾部插入 → 自动选中并聚焦第一个字段 → 右侧详情区滚动到视口 |
| 删除实体/关系/属性 | 轻量二次确认（行内展开"确认删除？[删除][取消]" 或 `window.confirm` 回退），危险按钮 hover 变红 |
| 编辑字段错误 | 失焦即校验，字段下方内联红字；错误字段列表在底部校验面板同步聚合 |
| 标识属性🔑 | 仅允许一个：勾选新标识时自动取消其它（radio 语义），而非当前"多选报错"。**定稿**：互斥在 UI 层处理，并移除设计器内既有"多选报错"校验提示，避免冲突；后端/数据模型不变 |
| 空态引导 | 右侧显示步骤化引导（① 左侧点选或新增实体 → ② 右侧填 id/名称 → ③ 校验通过后同步图谱），附"新增实体/关系"快捷按钮 |
| 列表搜索 | 实体/关系分组内搜索框（复用 #23 图谱搜索交互风格），无结果时显示"无匹配项" |
| 键盘可达 | 列表项 Tab 可达、Enter 选中；表单 Tab 顺序从左到右；`Esc` 关闭行内确认 |
| 图标（emoji） | 保留自由输入 + placeholder 提示；**定稿**：常用图标快捷选择面板列为「可选增强」，本轮可不做，下迭代再补（不阻塞 S1–S4） |

## 6. 实施范围与拆分（独立分支 `feat/designer-ui-redesign`）

| 步骤 | 内容 | 验收 |
|---|---|---|
| S1 | 设计 token + 全局按钮/表单字段 CSS（index.css 新增 `.btn/.field` 体系，不影响 OntologyEditor 等现有模块） | 现有页面无回归（视觉对比截图） |
| S2 | Designer.tsx 布局重构：左列表区 + 右详情区 + 底部校验面板；组件拆分为 `DesignerList`/`DesignerDetail`（同目录新文件） | 三栏 → 两区，选中态/空态可见 |
| S3 | 交互补全：二次确认、新增聚焦、内联校验、标识属性 radio 语义、列表搜索 | 走查清单逐项通过 |
| S4 | 回归 + 浏览器实测 | vitest 全绿（含既有 52 项，以 `npm run test` 实际输出为准）、tsc、build；走查 8 项清单逐项截图确认 |

**明确不做（本轮）**：拖拽排序、撤销栈（Designer 无 undo，沿用现状，**工具栏仅保留「重置」，不提供撤销/重做**）、图谱联动高亮（后续迭代）、移动端适配（桌面工具）；emoji 快捷选择面板列为可选增强。

## 7. 验收标准（走查清单）

1. 打开可视化编辑：左列表 + 右详情 + 底部校验三区块结构清晰，无滚动跳动
2. 选中实体：详情区平滑切换，字段有 label、焦点环、placeholder；hover 列表行有反馈
3. 修改 id 为非法值：失焦后字段下方红字提示，底部面板同步聚合
4. 删除实体：出现二次确认，确认后列表与图谱同步更新
5. 新增实体：自动选中并聚焦，详情区滚动可见
6. 勾选第二个标识属性：第一个自动取消，无报错
7. 空态（取消选中）：显示引导文案与快捷新增按钮
8. 校验分组（#22 行为保持）：阻断/必改/建议分组与点击定位不回退

## 8. 风险与说明

- **范围可控**：仅改 Designer 组件与 index.css（新增 token/按钮/字段体系），不动 store/数据层，OntologyEditor、图谱等其它模块样式不受影响（共用 `.btn` 的后续可渐进替换，非本轮目标）。
- **行为兼容**：校验逻辑、分组、点击定位等 #22 能力原样保留；数据模型（entityTypes/relationships）结构不变，后端无改动。
- **标识属性互斥**：由 UI 层实现"勾选即取消其它"的 radio 语义，并移除设计器内既有"多选报错"提示，避免新旧逻辑冲突；仅前端交互调整，后端/数据层不变。
- **实现代价**：S2 布局重构为最大工作量（组件拆两个文件），预估改动 Designer.tsx 约 150~200 行 + 新增 CSS 约 180 行；纯前端，无后端/测试基线变化。

待你审核确认后，按 S1→S4 在独立分支实施，测试与浏览器实测通过后等你确认再合并。

## 9. 评审定稿说明（2026-10-27）

本方案经评审，针对以下问题澄清并定稿（决议已并入上文对应章节，正文以"**定稿**"标注）：

1. **工具栏按钮与「明确不做」矛盾**：原布局图含 `[撤销][重做][重置]`，但撤销栈明确不做。定稿为工具栏仅保留 `[重置]`（语义：放弃当前未保存改动），不提供撤销/重做。见 §3 布局图与 §6 明确不做。
2. **测试基数核对**：S4 验收基数由"68 项"更正为"52 项"（项目前端 vitest 现状），并标注以 `npm run test` 实际输出为准，避免验收时数字打架。
3. **标识属性 radio 语义落地**：互斥在 UI 层实现（勾选即取消其它），并移除设计器内既有"多选报错"校验提示，避免新旧逻辑冲突；后端/数据模型不变。见 §5 与 §8。
4. **emoji 快捷选择面板**：由必做降级为「可选增强」，本轮不阻塞 S1–S4，下迭代再补。见 §5 与 §6。

定稿后按既定流程在独立分支 `feat/designer-ui-redesign` 从 S1 实施，S4 测试与浏览器实测通过后合并。
