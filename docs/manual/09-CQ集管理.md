# 09 CQ 集管理

> CQ（Competency Question，能力问题）集用来回答：**这份本体承诺回答哪些问题、其中多少条已经定位到本体证据、上次回归是否可答。**
> 本页覆盖前端「CQ 集」页、REST 端点、`/mcp/cq` 工具，以及一条 CQ 的完整字段规格。

## 9.1 页面与标签的分工

前端页头有三个平级入口（#203 由 5 项收敛为 3 项）：

| 页面 | 看什么 | 典型问题 |
|---|---|---|
| **图谱工作台** | 本体结构：类 / 属性 / 个体 / 推理边 | 「这个类下面有哪些个体？」 |
| **当前领域** | 这个领域包能做什么：定位、能力、约束、示例题 | 「这套本体适合问什么？」 |
| **CQ 集** | 这份本体答得上什么：题库、覆盖率、回归、审计 | 「哪些能力问题有证据？上次回归过了吗？」 |

CQ 集页内有两个标签：

| 标签 | 看什么 | 典型问题 |
|---|---|---|
| **题目** | 题库总览、逐题增删改、审计、评估与导入导出 | 「这道题凭什么答得上？」 |
| **训练** | 上区题看板（题卡 + 阶段条 + 待决内嵌决策卡 + 待我处理 + 题卷下钻），下区全部事件记录 | 「这道题走到哪了？要我做什么？当初怎么决的？」 |

时间线的类别筛选项是「全部 / 决策 / 观测·证据 / 回归 / 迭代 / 审计」；**迭代**不再是独立页面，按下后显示迭代档案卡片（业务话翻译 / 变更清单 / 闸门快照 / TTL 全文折叠）——「这轮 TTL 改动业务上意味着什么？」就在这里看。

题目页默认是**领导模式**（#210）：不出现 SPARQL 输入框与内部枚举，leader 只看业务语义与断言摘要，确认或驳回；需要直接改查询时显式切「专家模式」。训练页的决策卡带**现场上下文**（#211），并按「结论 / 依据来源 / 授权确认」结构化回收（#212）。

CQ 集页支持：总览看板（承诺 / 已定位 / 可答 / 缺口 + 两档覆盖率）、逐题增删改（专家模式：题干 / 题型 / 状态 / 来源需求 / SPARQL 断言；领导模式只确认或驳回）、变更审计、运行评估、导入导出（JSON / cq-test YAML / JUnit）。

## 9.2 数据位置

```
data/workspaces/<ontology_id>/
├── cq_set.json            # 当前 CQ 集（本页的读写对象）
├── cq_set.audit.jsonl     # 追加式变更审计
├── runs/<ts>.json         # 每次回归的历史结果
└── metrics.jsonl          # 北极星事件（cq_evaluated_real 等）
```

- 预置领域：`ontology_id` 是领域名（如 `agent_task`），首次访问从领域包内 `cq_tests.json` 播种；
- 导入的本体：`ontology_id` 是工作区 uuid（如 `55d67fad72ef`），与 REST / MCP 共用同一身份；
- 这些文件都在 `data/` 下、**不被 `scripts/backup.sh` 覆盖**，备份方式见 [04 运维 · 备份](04-运维与本体管理.md#43-备份)。

## 9.3 一条 CQ 的字段规格

整集骨架：

```json
{
  "suite": "agent_task_cq_regression",
  "version": 2,
  "cases": []
}
```

题目合法字段共 8 个：

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 否 | 稳定 id；缺省写入时自动分配 uuid |
| `cq` | **是** | 非空题干 |
| `expected_type` | 否 | 题型枚举；缺省补 `unknown`，填错 400 |
| `status` | 否 | 状态枚举；缺省补 `unset`，填错 400 |
| `requirement` | 否 | 来源需求标识（如 `REQ-1`） |
| `regression` | 否 | 回归断言，只允许 `{query, expect}`；留空则回归标 `not_tested` |
| `rule` | 否 | 退化定位用的规则标签（如 `R1` / `R3`） |
| `coverage_cache` | 否 | 最近一次回归回写的结论缓存，由系统维护 |

### 题型 `expected_type`

对齐 CQ4OE 基准：

| 值 | 中文 | 含义 |
|---|---|---|
| `retrieval` | 检索类 | 从图里取现成事实 |
| `derived` | 推导类 | 需要推理才有的结论 |
| `counting` | 计数类 | 期望一个数量 |
| `negative` | 反例类 | 期望「查不到」 |
| `unknown` | 未分型 | 合法兜底值；历史值 `set` 只读时显示为它，写入会被拒绝 |

> `derived` 与证明模块里的 `source=derived`（由推理产生而非断言）**同名不同义**，不要混用。

### 状态 `status`

`draft` 草稿 / `active` 启用 / `archived` 归档 / `unset` 缺失兜底。

### 回归断言 `regression{query, expect}`

`query` 必须是**非空 SPARQL**（SELECT 或 ASK，单一形态）。`expect` 支持裸 bool / 裸 int 简写，也支持显式判分对象：

| `expect.type` | 期望字段 | 语义 |
|---|---|---|
| `boolean` | `value`（布尔，默认 true） | 断言真假 |
| `exists` | `value`（布尔，默认 true） | 结果非空 / 为空 |
| `count` | `value`（整数） | 行数等于 N |
| `values` | `values`（数组） | 结果首列取值等于该数组 |
| `set_exact` | `values`（数组） | 结果首列集合精确相等 |
| `contains` | `values`（数组） | 结果首列包含全部期望值 |

完整示例：

```json
{
  "id": "T2-01",
  "cq": "哪些智能体可以执行「登录模块开发」？",
  "expected_type": "retrieval",
  "status": "active",
  "rule": "R1",
  "regression": {
    "query": "SELECT ?agent WHERE { ?agent <http://ontology.localhost/agent-task#can_execute> <http://ontology.localhost/agent-task#t_login_dev> }",
    "expect": {"type": "set_exact", "values": ["dev_agent", "junior_dev"]}
  }
}
```

## 9.4 已移除字段与迁移

0.8.3 起 CQ 只接受单一 SPARQL 断言（#179 / #180 / #181）。以下 7 个字段写入会得到定向 400：

| 旧字段 | 处理方式 |
|---|---|
| `tool` / `params` | 改为 `regression.query` + `regression.expect` |
| 平铺 `query` / `expect` | 移入 `regression` 对象内 |
| `anchor_terms` | 不再存储；定位由系统按题干自动计算（focus 模式仅在 `cq_author(draft=...)` 临时输入里用） |
| `priority` | 已移除 |
| `note` | 已移除；备注写进题干或 `requirement` |

示例错误：

```text
cases[0].tool：旧断言格式已移除：请改用 regression{query, expect}（#179）
cases[0].regression.expect.type 非法：'fuzzy'；合法值：boolean / exists / count / values / set_exact / contains
```

## 9.7 训练过程事件流

CQ 的训练过程不再散落在会话记忆里，而是**只追加**到 `data/workspaces/<id>/training_log.jsonl`。每行恰好六个顶层键：

```json
{"ts":"2026-11-15T00:00:00+00:00","event":"decision_asked",
 "ontology_id":"agent_task","actor_type":"human","actor":"web",
 "content":{"decision_id":"d-...","kind":"expectation","question":"...","options":["A","B"],
            "recommended":"A","reason":"...","background":"...","event_id":"..."}}
```

- 时间由服务端生成；`content` 整体收在一个对象里，不能覆盖时间 / 事件名；
- 事件分两族：**状态翻转族**（`decision_asked` / `feedback_received` / `decision_resolved_by_self` / `intent_pending_marked`）只能经 `cq_decision` 写入；**观测证据族**（出题 / 放行 / 回归 / 闸门 / 证据 / 迭代 / 熔断 / 归因）可经 `cq_training_write` 写入；
- 未知事件、缺必填、类型错、额外字段、题目不存在 → `invalid_event`，**不落盘**；
- 并发靠单行追加，不引入锁；坏行读取时跳过。

题目定义仍以 `cq_set.json` 为权威。网页建题 / 发题会补写 `case_authored` / `case_released` 留痕（操作者 `human/web`），MCP 路径为 `agent/mcp`；其余增删改仍只进审计，不写训练事件流。`summary.pending_decisions` 与 `cases[].intent_pending` 是**读接口层合并的视图字段**，直接读原始 `cq_set.json` 看不到。

## 9.8 决策入口与反馈

`/mcp/cq` 的 `cq_decision` 是唯一入口，动作固定三个：

| 动作 | 用途 | 必填 |
|---|---|---|
| `ask` | 提问（P0） | 类别（五类）、问题、选项 ≥2、推荐项（属于选项）、推荐理由、背景话术 |
| `feedback` | 反馈（P0 / P2） | 决策编号；反馈原文 / 所选选项 / 跟进对象 / 结构化结论 / 依据来源 / 授权确认可任意组合，**可全空** |
| `withdraw` | 自答撤问（P1，仅智能体侧） | 决策编号、自答方法 |

五类决策固定 `semantic / expectation / priority / term / scope`，不允许自定义。反馈**不设状态参数**：服务端只记一条 `feedback_received`，状态由读时投影判定——有可采纳结论 → 已裁决；无结论 → 待跟进；`decision_resolved_by_self` → 已撤回。回答来源由通道注入（REST `direct` / MCP `agent_relay`），调用方不可覆盖。

`feedback` 的结构化字段（#212）：

| 字段 | 取值 | 说明 |
|---|---|---|
| `conclusion` | `adopt` / `reject` / `defer` | 采纳推荐 / 驳回或改选 / 暂缓；`defer` 或未授权 → 待跟进 |
| `basis` | `self` / `expert` | 自己判断 / 已问他人确认（人名放 `follow_up_with`） |
| `authorized` | 布尔 | 是否确认可以按此决策执行；`false` → 待跟进 |

缺省这三个字段时沿用旧口径（有选项或原文即裁决），保证旧脚本兼容。

## 9.9 现场、缺口与时间线

- `cq_resume`：状态摘要、上次回归、待决、待跟进、熔断、迭代引用、按题目聚合的意图标记 + 决策议程 + `context_gaps` + `next_suggested`；默认 `snapshot`，`full` 附历史。实时聚合，不落快照。
- `cq_agenda`：从 CQ 集现场生成待决议程，覆盖未锚定题 / 质检问题 / 回归失败 / 覆盖缺口 / 冗余；每条含业务话 `background / question / options / recommended / reason`，编号按「类别 + 题号」稳定生成。只读、不落盘；前端只消费 `cq_resume` 合并后的 `pending_decisions`，不自行扫描 CQ 状态。
- 议程在第一次被回答时才惰性物化为一条 `decision_asked` 事件（归属智能体），因此读接口保持纯读，历史仍可追溯；同一「类别 + 题号」不会重复出题。
- **文案口径（#208 / #252）**：生成侧不写事件类型名 / 内部路径 / SPARQL 片段；前端 `plainCopy` 对决策背景、问题、选项、推荐理由、缺口与下一步做兜底去黑话；决策编号、类别与原始字段默认收进「展开看技术细节」，专家点开才显示。全局事件摘要一律中文（见 9.18）。
- 缺口规则 G1–G7：回归失败无归因、迭代缺业务话、待跟进超期、熔断未生成决策、迭代档案缺失、反馈无任何可采纳内容、题集为空需要智能体按当前本体生成候选题。G6 只提示不阻断；G7 出现时 `next_suggested` 直接给 `generate_cases`。
- `cq_timeline`：训练事件 + 审计 + 回归历史 + 迭代档案四源聚合，支持 `since / kinds / limit`；时间取自文件内容，不解析文件名。
- `cq_iteration_write`：写 `iterations/<id>.json`（业务话翻译 / 变更清单 / 闸门快照 / TTL），并连带记 `iteration_started / gate_result / iteration_applied / iteration_accepted`。

## 9.11 角色模型与北极星护栏指标（#206）

协同主线的角色边界只有一句话：**人担决策责任，智能体扛专业活**。

| 角色 | 只做 | 不做 |
|---|---|---|
| 人（leader） | 在 Web UI 看现场、读议程、逐条「采纳推荐 / 改选 / 暂缓」，必要时写「已线下找谁确认」 | 不写 SPARQL、不构造断言、不切本体内部状态、不补术语、不创作题目、不输入自然语言意图 |
| 智能体 | 经 MCP 出题 / 定位 / 质检 / 回归 / 议程；按人的决策落库、换路径、固化断言、导出 CI | 不替人拍板；不在后端做第二套独立自动机 |

闭环五步（硬约束，任何改造都不得让它模糊）：

1. 智能体驱动人：主动产出并推送待决事项，人不必自己发现该决什么；
2. 智能体经 MCP 生成数据：定位 / 质检 / 可答 / 缺口 / 建议题 / 议程全经 MCP 工具生成；
3. 人经 Web UI 看数据做决策：只在 Web UI 消费数据、给决策；
4. 智能体看人的决策进行下一步行动：采纳 → 落库 / 执行，驳回 → 换路径，确认预期 → 固化断言，锁定 → 导出 CI；
5. 新状态回到第 2 步，形成循环。

### 指标树（领导模型下仍全部保留）

- **质量驱动 5 条**：锚定 / 可答 / 质检 / 覆盖 / 去冗；
- **协作效率 4 条**：采纳率 / 往返轮次 / 自动修复率 / 决策时延——议程直接给选项，往返轮次与决策时延反而更顺；
- **其余护栏**：留存率 / 工具报错率 / cq-test 纳入 CI 率。

### 护栏三项（#247：有数据才出数，且是发布门禁）

| 指标 | 数据源与口径 | 发布阈值 | 无数据时 |
|---|---|---|---|
| 工具报错率 | `metrics.jsonl` 中窗口内 `cq_api_call` 里 `ok=false` 的占比；`cq_api_error` 只说明原因，不进分母 | ≤ 2% | `available=false` + 原因 |
| 毕业留存率 | 1 − 「删除时已毕业」题数 ÷ 曾毕业题数；毕业快照取删除时刻的集内字段（已分型 + 有断言 + 评估通过 + 未归档） | ≥ 90% | 没有毕业样本时 `available=false` |
| cq-test 纳入 CI 率 | 需要「导出过 cq-test」+「消费方声明」+「执行结果」三段证据 | ≥ 90% | 恒 `available=false`，不伪造 |

- 阈值在 `pipeline/guardrails.json`；`scripts/check_cq_guardrails.py` 读同一套计算，超阈非零退出，CI 中作为发布门禁（数据成熟前允许 `continue-on-error`）。
- 毕业留存率的「删除时毕业」是审计快照口径，与 CQM 的五条件（含本次锚点复核）有意不同：审计没有当次定位结果，不能用 CQM 反推历史。

### 两条新增护栏（把「主动告知」量化）

| 指标 | 定义 | 目标 |
|---|---|---|
| 决策面填充率 | 打开工作台时，系统主动呈现 ≥1 条可决事项的会话占比 | ≥90% |
| 主动决策议程覆盖率 | 自动生成的待决决策 / 应被提出的决策总数 | 逐步逼近 100% |

口径说明：

- 「可决事项」= `cq_resume.pending_decisions` 非空（智能体经 `cq_decision ask` 提出的 + `cq_agenda` 从现场推导并经 `resume` 合并的）；
- 采集随 P0 改造落地（本版先定义口径）；指标要求的是系统先开口，而不是让人自己发现问题；
- 工作区里的北极星 / 功能评估 / 系统改进方案三份文档与本页共用同一口径；本页是仓库内的口径基线，外部文档更新时以相同定义为准。

## 9.12 领导模式与结构化决策回收（#210–#212）

### 题目页：领导模式默认，专家模式显式切换

- **领导模式（默认）**：不显示 SPARQL query / expect，也不显示 `expected_type` / `status` 下拉；leader 只看到题干、业务语义（检索 / 推导 / 计数 / 反例）和一句断言摘要（「应判定为是」「应正好查到 3 条」「结果应包含：…」）。
- **确认 / 驳回**：确认后，有断言 → 状态自动置为启用；无断言 → 保持草稿并提示「等智能体补断言」。驳回 → 退回草稿，等智能体调整。两种动作都不要求 leader 写查询。
- **专家模式**：显式切换后才出现 SPARQL 与内部枚举，保留给真专家核对；切回领导模式即隐藏。
- 断言摘要由读视图字段 `assertion_summary` 提供（不落盘），MCP 与 REST 读到的是同一句业务话。

### 决策卡：现场上下文自包含（#211）

- 议程生成的每条决策卡带 `context`，用业务话说明「为什么问、这题现在卡在哪」，例如：「这题能对上本体里的『登录模块开发』，目前查到 6 条证据。上次回归没通过：实际结果和预期不一致。」
- 智能体经 `cq_decision ask` 也可传 `context`；前端卡片直接展示，不需要 leader 跳到题目页读 SPARQL。
- 原始编号 / 类别 / 背景 / 上下文仍收在「展开看技术细节」，默认收起。

### 结构化回收决策结果（#212）

- 决策卡按「结论（采纳 / 驳回改选 / 暂缓）→ 依据来源（自己判断 / 已问他人）→ 授权确认」回收，用户必须勾选授权后才能提交；选推荐项默认 `adopt`，选其他项记 `reject`，另设「暂缓」按钮。
- 结构化字段填充率直接用 `cq_resume.counts.structured_feedback / counts.feedback` 口径计算（三项齐全才计入），无需另建埋点。
- 回归失败 / 覆盖缺口自动框成决策卡：失败题给「改预期以匹配新结果 / 补本体后保持原预期 / 删除该题」三选一；**回归失败不占议程名额，100% 出卡**。
- 时间线保留结构化回执：结论、依据来源、是否授权；`withdraw` / 自答方法等实现词不再出现在 leader UI，统一显示为「该项已由智能体自行处理」。

## 9.13 题干提及覆盖（只读，#215）

用于回答「哪些类/属性从来没有被任何 CQ 题干提到」——不是「解答依赖哪些公理」：

- **口径**：元素全集 = 本体领域类 + 属性；「提及」= `cq_locate` 锚点与元素 label / 短名精确匹配。只认字面，同义、简称、隐含依赖会漏。
- **输出**：`summary`（题数 / 元素数 / 已提及 / 未提及 / 提及覆盖率 / 定位失败数）、`elements`（每个类/属性的 `case_ids`）、`uncovered`、`unmatched_anchors`（个体 / 枚举 / 分词锚点，不冒充类/属性）。
- **入口**：`GET /api/domains/current/cq/coverage` 与 MCP `cq_coverage`；前端在「专家模式 → 质量盲区（题干提及）」按需检查，领导模式不出现。
- **边界**：不落盘、不改 CQ / 训练 / 议程；不做公理级 provenance（#216 / #159-B），也不做多集（#217 / #159-C）。

## 9.14 题生命周期看板（#219）

训练标签从「按决策状态分块的日志面板」改为「以题为主语的看板」：

- **题卡是主语**：每题一张卡，显示当前阶段（已建题 / 回归中 / 待我决 / 已决 / 修复中 / 通过 / 待跟进）、阶段条与最近回归。
- **概览按题 roll-up**：待决 / 已决 / 待跟进都按题数，决策条数并列显示；点数字可筛题卡，熔断独立。
- **待我处理**：从「待决题」直达，只显示待决题，首题答题卡直接展开；提交后自动定位下一题，授权勾选保留。
- **这道题的记录**：题卡按钮 / 阶段条分段 / 答题中回看三个入口；事件按时间正序，支持主体（人 / 智能体 / 系统）与阶段双筛，人裁决高亮，技术细节折叠。
- **全部事件记录**：整轮跑分 / 整库保存 / 迭代归档放在下方「全部事件记录」，不再与单题轨迹混排；带涉及题的下钻入口。
- **数据来源**：`cq_resume` 新增 `resolved_decisions` 与 `lifecycle`（题卡投影）；`GET /cq/cases/{case_id}/events` 提供单题卷；R7 让网页建题 / 发题补写 `case_authored` / `case_released`，操作者为 `human/web`。
- **边界**：不改题库管理状态（草稿 / 启用 / 归档 / 未分型）；训练阶段是另一套词，两者不合并。事件流只追加、不迁移老数据、不做投影缓存。

## 9.15 首次用户可用性（#222–#233）

这一批只改「人看得懂数据」的呈现层，不改变智能体经 MCP 生成数据的逻辑：

- **概览口径**：定位覆盖 = 已定位 ÷ 承诺，可答覆盖 = 可答 ÷ 承诺，与计数卡同源；「缺口」统计未定位，「可答」统计回归通过，二者不是互补分类；趋势写明「较上次上升/下降 N 个百分点」；四个统计词与进度条均有行内说明。
- **题目详情**：一个定位状态只出现一段业务提示，重复的 `rdfs:label` / 术语总数等细节收进「展开看定位技术细节」；「上次评估」显示通过 / 未通过 / 尚未评估；断言的业务摘要默认可见，原始 query / expect 仍可折叠。
- **题目列表**：主标识改为序号 + 题干，完整 ID 收进详情技术信息；题干 hover 看全文；英文标识符标注「含本体标识符」；两条进度条各有口径说明。
- **训练页**：首屏「从这里开始」+ 可点击「下一步」直达待决；阶段条标注「点击查看该阶段的记录（回归可能反复）」；题卡仍可下钻事件流。
- **决策卡**：背景（为什么问）与现场依据（验收要求 / 最近回归）分工，不重复；选非推荐项时先提示结论联动，需显式「确认提交」，不再静默改值；「补充反馈 / 需要谁确认」在卡内可见。
- **术语与角色**：新增「术语说明」词典（CQ / 锚点 / 可答 / 回归 / 断言 / 题型 / 阶段 / 熔断等）；顶部有人机分工条（智能体最近做了什么 / 你有几件待决）；顶部显示当前题集、当前领域与本体加载时间，全部题目都未命中术语时显式告警「题集与本体可能不匹配」。
- **领导/专家边界**：领导模式只确认智能体生成的题与决策，不出现题干输入框、专业分类下拉、新建题目与导入入口；专家模式才提供题干 / SPARQL / 分类编辑，并解释四类题型含义。

## 9.16 北极星达标补齐（#235–#243）

- **CQM 与毕业态**：`CQM = 已毕业题数 ÷ 目标题量`；目标题量 = 本体关键术语数 × 0.5（最低 20），不随删题缩水。毕业 = 已锚定 + 已分型 + 有断言 + 上次回归通过 + 未归档；首页显示 CQM、已毕业/目标与五项质量分解，每张题卡可看「还差哪一条」。
- **决策→行动闭环**：人提交决策后，系统追加 `action_requested`（`actor_type=system`，动作如改预期 / 补本体 / 改问法 / 删题 / 重跑 / 生成候选题）；`cq_resume.next_actions` 供智能体拉取，执行完用 `cq_action_complete` 标记，行动从队列消失。领导模式「请求智能体生成候选题」写入 `generate_cases` 行动，人不写题干。
- **指标采集**：`GET /cq/metrics` 聚合决策面填充率、智能体建议采纳率、单题往返轮次中位数、决策时延中位数、CQM 与质量分解；`metrics.jsonl` 新增 `cq_decision_feedback` / `cq_action_requested` / `cq_workbench_viewed`。护栏三项（工具报错率 / 毕业留存率 / cq-test 纳入 CI 率）已接 `metrics.jsonl` / 审计 / 题集数据源，无样本时如实 `available=false`；同一套计算由 `scripts/check_cq_guardrails.py` 作为发布门禁读取。
- **归属真实**：议程由系统规则推导，物化事件与题卷都标 `system/cq`；采纳率只统计经 `cq_decision ask` 的真正智能体建议，避免规则产物冒充 agent。回归事件的操作者取自本次运行本身（网页 `human/web`、MCP `agent/mcp`），拿不到身份时标 `unknown`，不替任何一方代签。
- **集可信**：`cq/coverage.summary.likely_mismatch` 用「题集有题但覆盖提及为 0」判断错配；错配时页面告警且 CQM 不可用。题集播种时记录来源本体（`seeded_from`：领域 / 本体名 / 本体身份指纹 / 版本 / 时间），`GET /cq/set.provenance.stale=true` 表示当前本体与播种来源不一致，页面沿用同一告警位显示「不能作为成熟度依据」；导入态不再把领域包题集当成本体题集，空集通过 G7 引导智能体重新生成。
- **一致性**：训练题卡主标识改为序号，完整 ID 进技术信息；题集名显示「默认题集」并悬停看系统标识；`cq/set.summary.pending_decisions` 与 `cq/resume.counts.pending` 同源（都含议程）。
- **#242 说明**：工作区北极星基准文档不在本仓库，仓库侧口径以本页 9.11 / 9.16 为准；外部文档需按相同定义人工同步。

## 9.18 事件文案中文化（#252）

这一批只改「事件流怎么说人话」，事件与审计的落盘字段（`kind` / `event` / `action`）保持英文码不变。

- **摘要补全**：`_EVENT_LABELS` 与 `constants.TRAINING_OBSERVATION_EVENTS` 的 13 种事件一一对齐（新增动作请求 / 动作完成 / 查看工作台）；每类事件按语义给默认中文摘要（「查看了工作台」「请求执行动作：生成候选题」「动作完成：生成候选题（已完成）」），`content` 缺 `summary` / `reason` 时兜底为事件名本身，不再出现「记录：」空冒号。
- **审计与回归**：审计摘要用中文动作（初始化题集 / 保存题集 / 导入题集 / 新增题目 / 更新题目 / 删除题目 / 运行评估）并排题号；整轮回归显示「回归：20/20 通过」，逐题回归的 `cannot_tell` / `not_tested` 也翻成「无法判断 / 未测试」。
- **执行渠道**：时间线与题卷显示「人 · 网页」「智能体 · MCP 工具」「系统」；非渠道值（如人名）原样保留并带主体类型。MCP 属行业缩写，保留但配中文。
- **时间**：全部事件记录补上 `formatLocalTime()`，与其余面板同为本地时间、不带时区后缀（#250 R5 残留）。
- **映射收敛**：渠道 / 审计动作 / 事件徽标 / 机器行动 / 回归结论的中文映射只保留 `frontend/app/src/lib/cqLabels.ts` 一份，`CqPage` 与 `CqTrainingPanel` 不再各自维护；历史里已拼了 `save` / `pass` 的摘要由 `timelineSummaryText()` 在展示层兜底翻译，只改展示、不迁移数据。
- **守卫**：后端断言标签表覆盖 13 种事件、时间线摘要不以空冒号结尾且不含裸英文码；前端断言映射唯一，时间线渲染文本不含 `pass` / `save` / `web` / `mcp` 等裸码、时间不带 `+00:00`。

## 9.19 首次用户评审 P0：未知三态与决策卡（#255–#257 / #262 / #263）

- **待决三态**：概览「🧑 你」不再用 0 兜底——请求未返回显示「正在读取待决…」，取数失败显示「待决状态未知」并给重试，只有明确返回 0 才出现「当前没有待决」。

- **决策卡识别**：卡片首行改为 `#题号 · 题干片段（30 字截断）`；「待我处理」标题同步显示当前题号；提交回执改为「已记录决策 #题号 · 采纳推荐 / 暂缓 / 驳回改选」。
- **提交必确认**：任意选项（含推荐项）、暂缓、补充反馈都先出确认条，写明「将记为 X；提交后不可撤销」；不提供前端撤回（撤回仍由智能体经 `cq_decision` 发起）。

## 9.20 首次用户评审 P0/P1：可交付判定与指标口径（#258–#261 / #265 / #266）

- **交付判定**：`cq_resume.lifecycle.summary.delivery` 给出 `ready / missing_questions / unanchored_cases / failed_cases / cqm / cqm_if_unanchored_fixed`；页面顶部一行结论回答「差多少、差在哪、建议怎么办」，与 `cq/export?format=markdown` 的评审包同源。
- **CQM 达标线与差距**：CQM 旁常驻「交付线 100%（全部毕业）」与「补齐未锚定的 N 题到毕业 → X%」；公式不再当结论展示，收进「目标题量怎么算」技术细节。
- **目标题量口径**：实现与手册统一为 `max(20, 关键术语数 × 0.5)`，集中在 `cq_store.TARGET_QUESTIONS_K / TARGET_QUESTIONS_MIN`；页面写「按本体规模估算（可调）」，并注明 0.5 是初版估算法、待校准。
- **可答口径**：可答格标注「含 N 题未锚定」，避免「可答 100%」与「缺口 2」在同屏互相打脸。
- **智能体格**：有 pending 行动时显示「待响应 N 项：<动作>」；否则显示最近一次智能体动作 + 时间；再退化为「上一版题集更新于 X」，不再出现静态的「等待你确认或运行评估」。
- **来源与部分错配**：`provenance.known=false` 在题集名旁标「来源未记录」，CQM 下注明「成熟度仅供参考」；未锚定占比 > 10% 或 ≥ 2 题时出黄条并列出题号，与 `stale` 的红色告警并存不冲突。
- **评审包导出**：`GET /cq/export?format=markdown` 输出概览、逐题清单、风险清单与待决事项；导出菜单每项标注适用对象（参会的人 / 智能体 / CI / 测试平台）。

## 9.21 首次用户评审 P1/P2：等待状态、命名与可达性（#264 / #267–#271）

- **等待可见（#264）**：存在 pending 的 `action_requested` 时，概览常驻「⏳ 等待智能体 · 生成候选题 · 已等待 N 小时 · 未响应」，可「催一下」（追加一条带「催促」备注的请求）或「取消请求」；取消走 `POST /api/domains/current/cq/actions/{action_id}/complete`（`status=cancelled`），行动从 `next_actions` 消失。训练页顶部同步「智能体待办 N 项」。
- **命名统一（#267）**：全局称「全部事件记录」，单题称「这道题的记录」；「训练时间线」「全局历史」「卷」不再出现在界面与 `aria-label` 中。
- **领导模式去工程视角（#268）**：「质量盲区（题干提及）」只在专家模式出现；单题定位证据在领导模式只给一句 ≤30 字结论（如「对上 2 个术语、6 条证据」），原始命中明细留给专家模式。
- **文案批改（#269）**：「承诺」改「总题数」；题集更新时间注明「含导入 / 编辑时间」，本体加载时间注明「服务启动时间」；领域优先显示中文显示名（`agent_task` → 「智能体任务」），CQM 首次出现给全称提示；「来源需求」改「来自哪个需求」；页头副标题改为「本体推理 · OWL 2 RL」。
- **信息架构降噪（#270）**：熔断未触发时不再占统计格，改为一行「流程正常 · 熔断未触发」；已决 / 待跟进为 0 的统计格弱化；导出菜单每项标注适用对象；已锚定 / 毕业补一行内提示。
- **布局与可达性（#271）**：成熟度区块在 `resume` 返回前用等高骨架屏占位，避免首屏跳动；决策确认条出现后焦点自动落到「确认提交」；训练现场取数失败提供「重试」；术语说明改为右侧抽屉浮层，不再挤压主区列宽。

## 9.22 种子格式兜底与保存白名单（#275 / #278）

- **旧格式种子不再 500**：领域包 `cq_tests.json` 仍是 `tool` + `params` 旧格式时，第一次访问会抛 `SeedFormatError`；`GET /cq/set` 与 `GET /cq/resume` 返回 **422**，`detail` 含具体字段（如 `cases[0].tool`）和修复方式。失败路径不写 `cq_set.json`，不会留下半截题集，也不会把「题库坏了」伪装成「还没有题库」。
- **安装期拦截**：`domain install` / `domain install --from` 会先校验包内 `cq_tests.json`，非法种子直接拒绝安装并打印字段定位，避免部署后才炸。
- **保存只回传落盘字段**：前端 `CASE_WRITE_FIELDS` 白名单（`id / cq / expected_type / status / requirement / regression`）与 `cq/cq_store.py` 的 `_CASE_FIELDS` 对齐；`located / answerable / graduated / blockers / location / assertion_summary / intent_pending / coverage_cache` 等读视图字段不再写回。领导模式「确认题目与断言」与专家模式保存走同一条白名单路径。

## 9.23 退出导入态与分级清理（#276）

- **入口**：页头领域切换器旁，仅导入态显示「清除导入的本体」；默认领域下不渲染。
- **两层语义**：
  - 「退出导入并切回默认领域」——可逆、不删任何文件，只清 `_current.json` 与激活态；重启后不再恢复导入态。
  - 「一并删除磁盘数据」——展开两个粒度：**仅删本体源文件（默认）** 删 `source.owl` + `meta.json`，保留 CQ 题集 / 跑分 / 审计 / 训练日志；**全部删除** 连 CQ 工件一起删，需显式 `cascade_cq=true` 且二次确认不可逆。
- **接口**：
  | 方法 | 路径 | 说明 |
  |---|---|---|
  | `GET` | `/api/ontology/workspaces` | 工作区清单（本体大小 / CQ 题数 / 跑分次数 / 日志条数 / 是否当前） |
  | `GET` | `/api/ontology/workspaces/{id}` | 单个工作区详情（确认弹窗数据源） |
  | `POST` | `/api/ontology/exit-imported` | 退出导入态并切回默认领域；不删文件 |
  | `DELETE` | `/api/ontology/workspaces/{id}/source` | 只删本体源文件与元数据；当前导入态会先自动退出 |
  | `DELETE` | `/api/ontology/workspaces/{id}?cascade_cq=true` | 全删；未显式确认时 400 并说明会带走什么 |
- **审计**：`exit_import` / `workspace_source_delete` / `workspace_delete` 复用 CQ 审计格式；全删的审计写在默认领域，工作区删掉后仍可追溯。
- **边界**：不动 `data/uploads/`、不改导入机制与 CQ 存储位置、不提供回收站；路径穿越（`../`）与超长 id 一律 404。

## 9.24 切换领域后 MCP 同步跟随（#277）

- **MCP 侧**：新增控制面 `GET /control/status`、`POST /control/switch-domain`。换域时先按目标领域重建引擎 / 适配器（规则层与 API 同序），再**只增删工具注册表**——不重建 server、不断已建立会话；失败回滚到旧状态并返回原因。新增通用工具 `mcp_status`，任何领域下都可用；`/mcp/cq` 的 `ontology_id` 取自当前适配器，换域后自动跟随。
- **API 侧**：领域切换（`POST /api/domains/{name}/activate`）、导入本体与退出导入都会调用 MCP 控制面；响应新增 `mcp_synced` / `mcp_error`。MCP 未启动或不可达时领域切换照常成功，只记 warning。`GET/POST /api/domains/current/mcp-sync` 提供实时状态与一键同步。
- **页面**：页头显示「MCP 已同步」或「MCP 未同步 · 立即同步」（MCP 未运行时不渲染，避免误导）；切换后未同步会出黄条提示并可一键修复；说明页「MCP 接入」区显示 MCP 实际领域、工具数（含领域专属数）与一致性。
- **边界**：不改任何领域工具签名 / 返回结构；`/mcp/cq` 工具集不重建；不开放 MCP 侧自主切换；本期不做轮询兜底。


## 9.25 审核门控评估结论与页面配套（#279 / #280）

- **评估结论**：门按「写入 diff」判定（仅 status 非 active → active 时校验该题 review），`review` 整对象强校验并禁止单键 patch，翻批覆盖五条写路径；`active + pending` 视为非法（先退回 draft），`seed` / `import` 显式豁免。完整结论见仓库根目录 `docs/CQ_REVIEW_GATE_EVALUATION.md`。
- **页面配套**：题目行徽章、详情「审核」栏、「还差什么」统计与筛选、回归预检都会展示「待审核」；预检发现待审题时禁用「跑一轮评估」并说明会被拦住；服务端返回结构化 `review_pending` 时给出「有 N 道题还没有审核结论：#…」而不是「保存失败」。
- **命名**：统一「待审核」，与训练页「待决题」区分；训练页在有待审题时额外给出「有 M 题在等审核结论」。
- **前置**：必须先有 #278 的落盘白名单，否则前端会把旧 review 回传覆盖服务端状态。

## 9.26 审核门控服务端（#285）

- **字段**：题目可带 `review = {required, state, by?, at?}`，`state` 只允许 `none / pending / approved / rejected`；字段缺省 = 免审。非对象、`required` 非 bool、非法 `state`、`required=true` 缺 `state`、未知字段一律 400 并列出合法枚举。
- **门（diff 语义）**：只在写入结果出现「`status=active` 且必审未过」时拒绝，不做集级扫描；存量已处于该状态的题不因其它编辑反复报错。覆盖 REST PUT 整集、PATCH 单题、新增、MCP `cq_set_write`、`cq_case_upsert` 与导入直写字节分支；`seed` 播种豁免（领域包受版本管理）。
- **拒绝形状**：REST 400 `detail` 为 `{code:"review_pending", message, blocking:[{id,state}], total_pending}`，MCP 返回 `error.code="review_pending"` 并附同样字段。
- **自动重置**：仅 `regression.query/expect` 变化时把该题 `review` 重置为 `pending`（清空 by/at），若原本 `active` 同时退回 `draft`；改题干 / 需求 / 题型不重置。
- **其它**：`rejected` 题不参与回归（不进分母）；`build_view.blockers` 增加「待审核」并影响 `graduated`；审计 `_summary` 带 `review`，整集写入逐题记 `after`；评审包新增「审核」列。
- **边界**：不改 `graduated_snapshot` 历史口径；不把 `review` 写入训练事件流；不做集级门。

## 9.27 标识、导航与搜索（#288–#290 / #292）

- **套件名（#288）**：页面首屏显示真实 `suite`；「来源未记录」是独立徽章，不再与名称连排；系统标识留在「集信息 / 技术细节」。
- **稳定短号（#289）**：写入时生成 `Q01`、`Q02`…，删除不复用、排序不改；界面列表 / 详情 / 训练题卡 / 决策卡 / 事件流「看涉题」/ 评审包逐题表统一使用。历史题集读取时按存储顺序兜底显示，下一次保存即落盘。32 位哈希只作机器字段，保留在技术视图。
- **视图路由（#290）**：`#cq/cases` / `#cq/training` 与视图同步；刷新、粘贴 URL、前进后退均保持；页头显示「CQ 集 › 题目 / 训练」。
- **搜索（#292）**：题目列表新增搜索框，支持 `#Q03` / `Q03` / 序号、状态词（启用 / 草稿 / 待审核…）、题型词与题干关键词；与「还差什么」筛选叠加；搜索词写入 URL（`#cq/cases?q=…`）。


## 9.28 评估状态驱动与渐进披露（#291 / #293）

- **评估新鲜度**：`cq_resume.evaluation` 返回 `fresh / stale / none`，判据是上次回归时间与题集 `updated_at`、本体文件 mtime 的先后。页面与训练页共用同一份判断。
- **动作归属**：评估有效时全页不出现「跑一轮评估」；判定条只挂「请求智能体生成候选题 / 导出评审包」。评估过期（`stale`）或未评估（`none`）时，判定条出现「评估可能过期 / 评估未生成 + 重新验证」，确认框四条后果保留。训练页「下一步」在有效时改为「请求生成更多题」。
- **渐进披露**：删除领导 / 专家模式开关；页头「显示技术细节」开关（localStorage 记忆）控制 SPARQL、内部枚举、证据原文与质量盲区面板。编辑 / 新增入口常驻，编辑器把专业分类、状态与 SPARQL 收进「技术设置」折叠区，展开提示「改动断言会让这道题重新进入待审核」。

## 9.29 四槽位信息架构与降噪（#294–#298）

- **四槽位**：判定（交付判定条，持有生成 / 验证 / 导出动作）→ 质量（漏斗：总题数 → 对上本体 → 可答 → 毕业 / 目标）→ 内容（搜索 + 筛选 + 列表 + 详情）→ 元信息（CQM 明细、协同指标、集信息统一折叠在「质量明细与集信息」）。题目列表回到首屏范围内。
- **引导唯一化**：删除「从这里开始」静态剧本；首次访问只出现一次性横幅（`oa.cq.welcome.v1`），之后不再出现。判定条与训练页「下一步」共用评估状态（#291）。
- **可信度**：`provenance.known=false` 时判定条附「（来源未记录，仅供参考）」，CQM 旁出「来源未知」徽章。
- **词表与零值**：`缺口` 改为「没对上」，「还差什么」改为「未达毕业的原因」，覆盖统一叫「覆盖（有证据）/ 覆盖（回归通过）」；筛选 chip 0 值不占位；训练页阶段条在终态（通过）不渲染，阶段筛选隐藏 0 值。
- **规模**：列表与题看板超过 20 条分页加载（「显示更多」）；无待决时默认排序从「行动优先」自动切到「题号」，排序器保留当前规则。
- **评审包（#298）**：新增「差距分析」（目标题量按本体术语数 × 0.5 推导、缺口构成、建议动作）；判定句由后端 `delivery.verdict` 生成，页面与 Markdown 逐字一致；逐题表沿用稳定短号。
